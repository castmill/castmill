# Website package

`packages/website/` is the Docusaurus 3 documentation site served at https://docs.castmill.io. The contributor guide, chapter layout, MDX components and style guide are in `packages/website/README.md`; agent rules are in `packages/website/AGENTS.md`.

## Content structure

| Folder | Audience | Content |
| --- | --- | --- |
| `docs/getting-started/` | Everyone | Quick start with Docker, first sign-in, first screen |
| `docs/concepts/` | Everyone | Architecture, networks, organizations, users and teams, roles, content model |
| `docs/dashboard/` | Content managers | One page per dashboard area |
| `docs/players/` | Installers | One page per player platform, offline playback, troubleshooting |
| `docs/administration/` | Operators | Self-hosting, configuration, admin tool, network administration, plans and quotas |
| `docs/developers/` | Developers and agents | APIs and webhooks, MCP server, addons, player library, contributing, widget development |
| `docs/reference/` | Everyone | Glossary, FAQ |

The sidebar is autogenerated from these folders (`_category_.json` per folder, `sidebar_position` per page), so a new chapter is a new folder.

## Build pipeline

- The site embeds `@castmill/player` for live widget examples, so `@castmill/cache` and `@castmill/player` must be built first (`yarn build:website` from the root does both).
- `onBrokenLinks: 'throw'` makes the build fail on broken links.
- `plugins/llms-txt` generates `/llms.txt` from the sidebar and page descriptions.
- `plugins/social-cards` generates social card templates; see [SOCIAL-CARDS.md](./SOCIAL-CARDS.md).

## Design

- Theme tokens for both colour modes are in `src/css/custom.css` (Infima `--ifm-*` overrides and `--cm-site-*` tokens).
- The home page is `src/pages/index.tsx` with `src/components/HomeShowcase`.
- Global MDX components are registered in `src/theme/MDXComponents.tsx`.

## Screenshots

Dashboard pages show screenshots with the global `Screenshot` component, which picks `static/img/screenshots/<id>-light.webp` or `<id>-dark.webp` to match the colour mode. The images are captured from a fictional demo network ("Harbor Kitchen" and other organizations, `@example.com` users, generated slides and video) by the scripts in `packages/website/scripts/screenshots/`:

- `bootstrap.exs` creates the network, organizations, users and dashboard tokens in an empty development database;
- `seed.mjs` creates the content through the dashboard API, and `players.mjs` runs browser players so devices are online;
- `shots.mjs` lists every shot (page, preparation steps, capture area) and `capture.mjs` captures each one in both themes.

When a dashboard page changes, capture its shots again (`node scripts/screenshots/capture.mjs <id>`). Never commit screenshots of real accounts. See `scripts/screenshots/README.md` for the setup.
